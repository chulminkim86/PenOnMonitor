# PenOnMonitor — 바로 쓰는 필기 도구

문서·영상·웹페이지 등 지금 보고 있는 화면 위에 바로 필기하거나, 화면 전체를
흰 판으로 덮고 판서한다. Windows 전용.

## 실행

```
ScreenPen 실행.bat
```

또는

```
pythonw screenpen.py
```

필요 패키지는 Pillow 하나뿐이다 (`pip install pillow`). 나머지는 표준 라이브러리.
두 번 실행되지 않는다. 이미 떠 있는데 또 실행하면 안내만 띄우고 종료한다.
(이전 인스턴스가 남아 있으면 전역 단축키를 선점해 새 인스턴스의 단축키가 전부
죽기 때문이다.)

## 세 가지 상태

| 상태 | 화면 | 마우스 |
|---|---|---|
| **통과 모드** (기본) | 필기 내용만 화면 위에 떠 있음 | 아래 프로그램으로 그대로 통과 |
| **그리기 모드** | 화면을 순간 캡처해 배경으로 고정, 파란 테두리 | 오버레이가 받아서 필기 |
| **화이트보드** | 화면 전체를 흰 판으로 덮음, 확대/축소 가능 | 오버레이가 받아서 판서 |

- **그리기 모드** — 툴바 오른쪽 스위치 또는 `F8`
- **화이트보드** — 툴바의 `화이트보드` 버튼 또는 `Ctrl+0`. 그리기가 켜져 있든
  꺼져 있든 곧바로 전환된다.
- **Esc** — 어느 상태에서든 전부 해제한다. 화이트보드에서 나오고, 그리기를 끄고,
  **화면에 한 필기를 지운 채** 대기 상태로 돌아간다. 화이트보드 판서는 남는다.
  실수로 지웠으면 그리기를 켜고 `Ctrl+Z`로 되살릴 수 있다.

**필기는 두 벌로 따로 보관된다.** 화면에 한 필기와 화이트보드 판서는 서로 섞이지
않고 되돌리기 이력도 각각이다. 화이트보드에서 나갔다가 다시 들어와도 판서와
확대율·위치가 그대로다. `전체지우기`와 `지우개`는 지금 보고 있는 판만 지운다.

툴바는 어떤 상태에서도 항상 보이며, 상태를 전환해도 사라지거나 깜빡이지 않는다.

## 단축키

전역 단축키 — 초점이 어디에 있든 동작한다.

| 키 | 동작 |
|---|---|
| `F8` | 그리기 모드 켜기/끄기 |
| `Ctrl+0` | 화이트보드 켜기/끄기 |
| `Esc` | 전부 해제 (화이트보드 판서는 유지) |
| `F9` | 전체 지우기 |
| `Ctrl+Alt+S` | PNG로 저장 |
| `Ctrl+Alt+Q` | 종료 |

`Esc`는 **되돌릴 상태가 있을 때만** 가로챈다. 그리기·화이트보드가 켜져 있거나
화면에 필기가 남아 있는 동안에만 잡고, 대기 상태가 되면 즉시 놓아주므로 평소
다른 프로그램의 `Esc`를 방해하지 않는다.

오버레이가 입력을 받는 동안(그리기·화이트보드)만 동작하는 키. 전역으로 잡으면
브라우저의 탭 전환이나 실행 취소를 늘 가로채므로 일부러 이 범위로 두었다.

| 키 | 동작 |
|---|---|
| `Ctrl+1` ~ `Ctrl+4` | 펜 / 지우개 / 사각 / 형광 |
| `Alt+1` ~ `Alt+3` | 검정 / 빨강 / 파랑 |
| `Ctrl+휠`, `Ctrl+PageUp`/`PageDown` | 굵기 1~50pt |
| `휠`, `PageUp`/`PageDown` | 화이트보드 확대 / 축소 |
| `H` | 화이트보드 손 도구 — 끌어서 이동 |
| `Ctrl+Z` / `Ctrl+Y` | 되돌리기 / 다시 실행 (툴바에는 두지 않았다) |
| 가운데 버튼 드래그 | 화이트보드 이동 (손 도구를 켜지 않아도 된다) |
| 오른쪽 클릭 | 전부 해제 (`Esc`와 같다) |

툴바의 각 버튼에 마우스를 올리면 해당 단축키가 툴팁으로 뜬다.

## 모양

툴바는 글래스모피즘이다. 뒤에 있는 것이 흐리게 비치는 반투명 흰 판 위에 내용이
얹히고, 위쪽 테두리가 더 밝으며, 모서리는 둥글다. 뒷배경은 0.4초마다 다시 계산해
아래 내용이 바뀌면 따라간다.

## 도구와 색상

- **펜** — 자유 곡선
- **지우개** — 커서가 닿은 획을 통째로 지운다
- **사각** — 드래그하는 동안 미리보기가 따라온다
- **형광** — 반투명(디더링) 굵은 선. **색상 선택과 무관하게 항상 노란색**
  (`#FFE24D`)이다.

색상 3종. 배치 순서가 곧 단축키 번호다.

| 키 | 이름 | 값 |
|---|---|---|
| `Alt+1` | 검정 (기본) | `#0D0D0D` |
| `Alt+2` | 빨강 | `#A20000` |
| `Alt+3` | 파랑 | `#2569A7` |

### 굵기

굵기 메뉴는 없다. **`Ctrl+휠`로 1pt부터 50pt까지 연속으로** 고르며, 그리기 모드와
화이트보드에서 똑같이 동작한다. 굵기를 바꾸는 동안 커서 옆에 실제 크기의 원과
`12 pt` 같은 숫자가 잠깐 떠서 눈으로 확인할 수 있다.

**굵기는 도구마다 따로 기억한다.** 기본값은 펜 5pt, 사각 5pt, 형광 24pt,
지우개 20pt이다. 형광을 굵게 써 두고 펜으로 돌아와도 펜 굵기는 그대로다.

## 화이트보드

- **확대/축소** — 그냥 휠을 돌린다. 커서 아래 지점을 고정한 채 확대되고, 배율은
  25%~800% 범위다.
- **이동** — `H`를 눌러 손 도구를 켜면 왼쪽 버튼으로 끌어 옮길 수 있다. 손 도구가
  켜지면 커서가 손 모양으로 바뀐다. 다시 `H`를
  누르거나 도구를 고르면 풀린다. 손 도구를 켜지 않아도 가운데 버튼 드래그로 옮길
  수 있다.
- 획의 굵기도 배율을 따라간다.

## 로고

툴바 왼쪽 로고는 이 폴더의 `logo.png`를 읽는다(`logo.gif`/`jpg`/`webp`도 인식).
원본의 흰색·투명 여백을 잘라낸 뒤 높이 22px로 맞추고, 창 테두리와 구분선까지의
여백이 같아지도록 배치한다. 파일이 없으면 `::` 표시로 대체된다.

## 저장

`~/Pictures/ScreenPen/screenpen_YYYYMMDD_HHMMSS.png`에 저장된다. 툴바, 테두리,
굵기 표시는 빠진다. 통과 모드에서 저장하면 그 순간의 실제 화면 위에
필기가 얹힌 상태로, 화이트보드에서 저장하면 흰 판과 판서만 캡처된다.

## 구현 메모

- 오버레이는 `overrideredirect` + `-topmost` 전체화면 Tk 창이며, 배경을 매직
  컬러(`#FF00FE`)로 칠하고 `-transparentcolor`로 투명 처리한다. 통과 모드에서는
  확장 스타일에 `WS_EX_TRANSPARENT`를 넣어 창 전체가 마우스를 무시하게 만든다.
- **전역 단축키는 전용 스레드가 소유한다.** `RegisterHotKey`가 보내는 `WM_HOTKEY`는
  등록한 *스레드*의 메시지 큐로 들어오는데, 이걸 Tk 메인 스레드에서 받으려 하면
  Tk 의 메인루프가 큐를 먼저 비워 버려 단축키가 대부분 유실된다. 그래서 자기
  `GetMessage` 루프를 가진 스레드를 따로 두고, 받은 번호만 큐에 담아 메인
  스레드가 꺼내 처리한다. Esc 등록/해제도 `PostThreadMessage`로 그 스레드에
  요청한다.
- 단축키 처리 루프는 어떤 예외가 나도 다음 회차를 반드시 예약한다. 한 번이라도
  끊기면 전역 단축키가 통째로 죽기 때문이다. 예외는 `screenpen.log`에 쌓인다.
- **창을 `WDA_EXCLUDEFROMCAPTURE`로 화면 캡처에서 제외한다.** 덕분에 배경을 찍을
  때 창을 숨겼다 되돌릴 필요가 없어져, 모드 전환 때 툴바가 사라지거나 화면이
  멈추는 현상이 없다. 저장할 때만 오버레이를 잠깐 캡처 대상에 도로 넣는다.
  이 기능이 먹는지는 시작할 때 8px 시험 창으로 실제 확인하고, 안 되면 예전처럼
  창을 잠깐 숨기는 방식으로 물러난다.
- **툴바는 유리(글래스모피즘)로 그린다.** Tk 에는 `backdrop-filter` 도 알파도
  없어서, 툴바 뒤 영역을 직접 캡처해 흐린 뒤 흰 틴트를 얹은 그림 한 장을 만들어
  깐다. 글자와 스위치만 캔버스 항목으로 그 위에 올려 또렷하게 남긴다.
  모서리는 Windows 11 의 `DWMWA_WINDOW_CORNER_PREFERENCE` 가 다듬는다.
  뒷배경은 상태에 따라 출처가 다르다. 통과 모드는 실제 화면(우리 창은 캡처에서
  빠지므로 뒤가 그대로 찍힌다), 그리기 모드는 이미 들고 있는 정지 화면,
  화이트보드는 흰색이다.
- **뒷배경은 GDI 로 그 영역만 가져온다.** PIL 의 `ImageGrab` 은 영역을 지정해도
  화면 전체를 먼저 뜬 뒤 잘라내서, 7680x2160 에서 한 번에 127ms 가 걸렸다.
  `BitBlt` + `GetDIBits` 로 툴바 크기만 복사하니 15ms 로 줄었고, 유리를 다시
  계산하는 비용이 18ms, 호버로 알약만 다시 그리는 비용이 2ms 다.
- **확대가 버벅이던 진짜 원인은 우하단의 배율 표시였다.** 캔버스 구석에 `140%`
  글자를 두고 매 프레임 갱신하면, 그 구석과 좌상단 필기 영역을 한꺼번에 덮는
  갱신 영역이 프레임마다 생겨 사실상 화면 전체(16.6 MPix)를 다시 칠하게 된다.
  획 20개짜리 빈 판에서도 프레임 간격이 44ms(23fps)까지 벌어졌다. 이 표시는
  지금 아예 없애서 12.8ms(78fps)가 되었고, 25ms를 넘는 프레임이 사라졌다.
  같은 이유로 캔버스 위에 상시 갱신되는 표시를 두지 않는다.
- **확대는 두 단계로 부드럽게 만들었다.**
  1. 휠은 *목표* 배율만 바꾸고, `after` 루프가 지수 보간으로 목표까지 12ms마다
     쫓아간다. 그래서 한 칸 굴려도 뚝 끊기지 않고 흘러간다.
  2. 각 프레임은 필기를 다시 그리지 않고 `canvas.scale` 로 이미 있는 아이템의
     좌표만 변환한다. 획 150개 기준 한 프레임 비용이 전체 재렌더 1.0ms에서
     0.06ms로 약 17배 줄었다. 선 굵기는 애니메이션이 끝날 때 한 번만 정확히
     맞춘다. 이동(`손 도구`, 가운데 버튼)도 같은 이유로 `canvas.move` 를 쓴다.
- 필기는 `Surface` 두 개(화면용·화이트보드용)에 나눠 담는다. 각 `Surface`가 획
  목록, 되돌리기 스냅샷 80단계, 확대율과 이동량을 들고 있고, 그릴 때만
  `scale`/`ox`/`oy`로 변환한다.
- 창은 모든 모니터를 합친 가상 화면 전체를 덮는다(`SM_XVIRTUALSCREEN` 계열).
  모니터별 DPI 인식을 켜서 캔버스 좌표와 캡처 좌표를 일치시킨다.

## 문제가 생기면

`screenpen.log`에 시작 기록, 상태 전환, 예외가 남는다. 단축키가 안 들으면 이
파일에 `RegisterHotKey 실패`가 있는지 먼저 확인한다. 등록에 실패한 단축키는
시작할 때 화면 아래에 안내로도 뜬다.

## 알려진 제약

- Windows 전용. `WDA_EXCLUDEFROMCAPTURE`는 Windows 10 2004 이상에서 동작한다.
- **`Ctrl+0`을 전역으로 잡으므로, 브라우저·편집기의 "배율 초기화"가 ScreenPen이
  떠 있는 동안 동작하지 않는다.** 거슬리면 `_register_hotkeys`의 5번 항목을
  `Ctrl+Alt+0` 같은 조합으로 바꾸면 된다.
- 그리기 모드에서는 화면이 정지되므로, 재생 중인 영상이나 스크롤에 실시간으로
  따라 그릴 수는 없다. 통과 모드로 나왔다가 다시 들어가면 배경이 갱신된다.
- 형광펜의 반투명은 Tk 캔버스에 알파가 없어 디더링(stipple)으로 흉내 낸다.
- **필기가 300획을 넘으면 확대가 다시 느려진다.** Tk 캔버스는 GPU를 쓰지 않고
  CPU로 그리기 때문이다. 측정값은 20획 13.0ms, 100획 13.2ms, 300획 27.5ms,
  800획 62.7ms. 일반적인 판서(수십 획)에서는 문제가 없지만, 판을 무겁게 쓰는
  것이 일상이 되면 렌더링만 GPU를 쓰는 라이브러리(예: Qt QGraphicsView +
  OpenGL)로 옮기는 것이 답이다. 파이썬 자체의 비용은 프레임당 0.03~0.15ms로
  전체의 1% 남짓이라 언어를 바꾼다고 해결되지 않는다.
